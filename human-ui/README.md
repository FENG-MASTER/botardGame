# 围桌 · 人类客户端

独立的桌游平台 Web UI，通过 HTTP API 与游戏服务器通信。人类和 agent 使用同样的房间、权限和回合规则。当前包含 FCM 可视化棋盘与各阶段操作表单；其他游戏可扩展自己的视图。

## 启动

需要 Node.js 22.13+，推荐 Node.js 24。运行时无 npm 依赖，无需构建。

先在后端项目根目录启动游戏服务器：

```sh
uv run --locked python -m boardgame.server
```

另开终端启动本工程：

```sh
cd human-ui
npm start
```

打开 <http://127.0.0.1:5173>。不启动后端也可以访问 <http://127.0.0.1:5173/#preview> 查看演示棋盘；演示不保存对局。

## 开始玩

1. 输入昵称并“入座”。如果服务器启用了注册口令，展开口令输入项填写。
2. 创建 FCM 房间时选择人数和要启用的扩展（可多选，留空为基础版），把房间 ID 和邀请码发给其他人类或 agent。所选人数全部入座后，由房主开始游戏。六人局需要勾选六人游戏和新城区。
3. 自己试玩可以用普通窗口和无痕窗口各创建一个身份，分别控制两个座位。客户端不会自动添加机器人。
4. 根据阶段操作：摆放餐厅、选择储备金、安排组织结构、选择顺位、提交经营计划。地图可选择位置及绘制采购路线，也能通过坐标表单输入。
5. 经营计划可先检查再提交；服务器负责判断是否合法。其他玩家行动后界面自动刷新。侧栏“玩法手册”从服务器 MCP 读取当前规则说明。

无可安排员工的重组、最后一个顺位、无裁员选择且付得起的发薪、空库存或无冰柜的清理会由服务器自动完成。游戏记录显示原因。经营面板隐藏没有对应工作员工的能力项；仍保留已有草稿，便于修正。实际的招聘、裁员、冰柜取舍等选择由你决定。

身份凭证保存在当前标签页的 sessionStorage。请在“账户与身份凭证”中保存凭证，之后可用凭证恢复身份。房间与对局由后端保存；前端不维护另一份游戏数据库。

## 独立部署

整个 human-ui 目录可以单独复制部署，不依赖 Python 源码。启动配置示例：

```sh
HOST=0.0.0.0 PORT=5173 GAME_API_URL=http://backend:8000 npm start
```

- `GAME_API_URL`：游戏 API 的 HTTP(S) origin，默认 `http://127.0.0.1:8000`，不能带路径或凭证。
- `HOST`：默认 `127.0.0.1`。
- `PORT`：默认 `5173`。

Node 服务同时提供静态文件和 `/api/` 同源代理；浏览器请求经该代理转发到游戏服务器。使用其他静态托管服务时，也必须配置相应代理。公网部署请在反向代理配置 HTTPS。

## 检查

```sh
npm ci
npm run check
npm test
```

测试依赖 jsdom，涵盖棋盘交互、各阶段表单、计划生成、请求绑定、身份请求与幂等重试。它们不代替真实浏览器和真实服务器的完整联调。禁止子进程测试通信的环境可运行 `node --test --test-isolation=none tests/*.test.mjs`。

当前 FCM 使用 TTS 原图板块，支持开房选择全部 17 个扩展模块，冲突组合由前后端校验。说客建设、培训建咖啡店、乡村广告、食品工资和里程碑奖励选址均有操作表单。房间玩法手册从 MCP 读取本局配置及扩展说明。请以服务器返回的模块可用性和实现说明为准。

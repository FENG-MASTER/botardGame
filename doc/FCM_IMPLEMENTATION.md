# FCM 实现范围与规则来源

当前引擎 `0.3.0`，游戏 ID `fcm`。这是开发实现，未声明官方完整一致性认证。用户已明确不需要兼容旧版本游玩数据；不再维护旧引擎副本。

## 来源与基础校正

基础规则与 FAQ：`doc/fcm/FCM_Rules_EN_v3.pdf`、`doc/fcm/FCM_FAQ_v4.1.pdf`。扩展规则取自用户提供的 Workshop 2202544434 包内英文 2019 规则。资源来源、索引和检查证据见 `doc/fcm/tts-audit/README.md`。

已转录基础 20 张及新城区 6 张 5×5 板块，保留 GUID、图源、格子语义和房屋编号；默认地图按种子不重复抽取并旋转。前端显示对应本地贴图，规则使用服务器网格。13、17 号基础资源索引的交叉口是桥梁，不能转弯。公寓用字符串 ID `π`、`9¾` 并单独记录晚餐排序。

新建房屋编号为 1、3、6、9、11、14、17、19。员工供应、晋升箭头、可招聘标记已校正；例如定价经理可直接招聘且免薪，培训师免薪，汉堡/披萨主厨是 `1x` 职位。五人基础卡池共 222 张非 CEO 员工。营销板块按尺寸转录，不再全部为 1×1。

## 模块状态

全部 17 个模块可在开房时选择：新城区、说客、新里程碑、咖啡、泡菜、寿司、面条、番茄酱、薯条大厨、夜班经理、大众营销员、乡村营销员、美食评论家、电影明星、储备价格、艰难抉择、六人游戏。机器可读状态为 `game.modules[].available`；“新里程碑”和“艰难抉择”不能同时启用。

说客有有限形状组件、道路施工与路障、公园加价、首次使用新增地图；咖啡有培训建店、咖啡店范围起点、最短板块路线/最多杯数/歧义停靠点处理和清理奖励选址；乡村有永久巨型广告、三枚高速出口、无限需求与最后消费；新里程碑替换基础里程碑并包含可选择的额外营销、食品工资、工作员工培训及晚餐中断选址。所有玩家决策通过统一 API；人类 UI 有对应表单，MCP 返回规则及行动 Schema。

基础流程涵盖摆放、秘密储备与组织、顺位、招聘培训、营销、生产采购、开发开店、晚餐、小费/CFO、薪资、需求结算、冷藏及终局。无决策阶段由服务器原子推进，有裁员/冷藏等选择时仍等待玩家。

夜班重复能力、大众营销重复阶段、替代食品优先级、番茄酱来源与授予时点、模块配置持久化等有回归测试。另有新增四模块的专项与 UI 回归测试，包括咖啡歧义路线、说客地图平移、特殊里程碑工资、披萨电台中断后持久化恢复。测试通过不等同于穷举全部模块组合和官方 FAQ。

负价格连锁破产等基础边界仍应进一步与 FAQ 核对。当前发薪、清理采用玩家分别提交的决策边界；操作不可撤销。无聊天、倒计时、断线弃权裁定。

## 开房配置

HTTP 示例（MCP 把 `game` 改为 `game_id`）：

```json
{"game":"fcm","capacity":2,"config":{"modules":["sushi","kimchi","ketchup"]}}
```

空数组或省略 `modules` 表示基础版；不能重复、不能填未知或未开放模块。六人要求 `six_players` 和 `new_districts`；入门模式不混用扩展。所有组合限制见 `FCM_EXPANSIONS.md`，前端和后端都校验。

## 自定义场景

`config.scenario` 可覆盖 `board`、`stock`、`campaign_tiles`。`stock` 必须覆盖本局所有已启用非 CEO 职位。初始地图宽高为 5 的倍数、最多 30 格；格子语义包含普通道路、桥梁、房屋、饮料点和公园。房屋记录必须覆盖房屋格，普通为 2×2，花园 2×3，公寓 3×3。`tiles` 元数据用于显示原图，自定义地图可省略。规则库仍保留开发棋盘生成器用于单元测试，它已不是默认开局地图。

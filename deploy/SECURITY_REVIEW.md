# 公网安全核查（2026-11-06）

范围：代码路由、房间权限、线上配置布尔值核验、少量匿名 HTTP 探测。本记录不是完整渗透测试或安全保证。

## 已确认

- 身份、房间列表、房间状态、行动、事件接口及全部 MCP 请求要求 Bearer token。
- 房间读取、事件、行动验证／提交要求房间成员身份；加入需要邀请码；开始游戏要求房主；员工及阶段操作由规则引擎检查。
- token 为 32 随机字节生成的 URL-safe 字符串，数据库存 SHA-256 哈希；原始 token 不在 API 中供他人读取。
- 公开接口：GET /health、/openapi.json、/v1/games 及游戏目录描述。公开内容是健康状态和静态规则，不是对局。
- 注册 POST /v1/identities 支持 X-Registration-Key，但旧版线上 BOARDGAME_REGISTRATION_KEY 未配置，曾允许公开注册；现已改为强制用户邀请码，见下方更新。
- 公网匿名 GET /api/v1/me、/api/v1/rooms、房间状态／actions／events、/api/mcp 全部返回 401。
- 公网 /boardgame.sqlite3、/.env、/server.mjs 返回 404。UI 静态文件有路径白名单；数据库在独立后端挂载中，后端未直接映射公网端口。

## 当前需要加固的事项

1. 线上为 HTTP，未配置 TLS。Bearer token 可被传输链路上的攻击者获取和重放；应优先部署 HTTPS，并让人类与 agent 更新 URL。不能仅凭存在鉴权宣称安全。
2. 当前开放注册，未见注册／建房／长轮询请求速率限制及全局并发配额；攻击者可创建账号后消耗 CPU、线程和磁盘。私有试玩宜配置注册口令；公开平台则需要注册滥用防护与限流。
3. token 当前没有过期、用户主动吊销或轮换接口。token 泄露后的恢复机制需要补充。

本节为加固前的核查记录，未创建测试账号、房间或行动。

## 已实施更新（2026-11-06）

用户授权后已上线邀请机制和 HTTPS。当前使用自签名证书，可信连接需客户端正确加载公钥证书；不能因连接加密就忽略证书信任校验。明文 HTTP 不再提供业务服务。

注册必须有已登录至少 3 个不同自然日的老用户生成的一次性邀请码。生成有库存和每日额度限制，数据审计、使用原子性、过期和撤销已实现。原账号及 token 不变。

仍未实现全局请求限流／并发配额及 token 吊销轮换，不能把本次改动描述成完成所有安全防护。部署与验证记录见 README.md 和 INVITATIONS.md。
